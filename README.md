# thermal-shape-scale-h200 — 처음 보는 환경의 열화상 깊이 추정

열화상 한 장으로 실제 거리(m)를 추정하는 모델이 학습에 쓰지 않은 열화상 데이터에서도 되게 하려는 실험의 H200 실행 묶음이다. 깊이 정답은 MS2에만 있고, 평가 대상과 무관한 RGB-열화상 쌍에 고정된 RGB 선생(UniDepthV2)의 라벨을 붙여 학습을 넓힌다. 데이터와 가중치는 저장소에 없고 실행할 때 받는다.

설계, 선생 점검, 데이터를 만든 방법, 판정 기준을 고정한 경위는 [docs/DETAILS_ko.md](docs/DETAILS_ko.md)에 있다.

## 현재 상황 (2026-11-23)

- **문제.** 기준선(Depth Anything V2 ViT-L을 MS2로 미세조정)은 MS2에서 선행 수준이지만(AbsRel 0.071) 처음 보는 곳에서 무너진다(ViViD 밤 0.13, STheReO 0.45, FIReStereo 0.69, ViViD 실내 2.1).
- **쌍을 더하는 방법은 세 번 시도했고 어느 것도 '여러 곳에서 개선'에 이르지 못했다.** 모양만 가르치기(실험 2, 세 시드로 판정), 모양 + 스케일 학생(본 실험 3), 두 단계 구조 + 쌍(본 실험 4). 뒤의 둘은 시드 하나에서 차이가 잡음 폭의 6배 이상이라 멈췄다.
- **본 실험 4에서 본 것.** 쌍의 선생 라벨은 모양을 좋게 하고 스케일이 크게 틀린 곳(ViViD 실내, FIReStereo)을 고친다. 대신 STheReO의 스케일과 MS2의 모양을 나쁘게 한다(기존 구조 `mtd`에서도 같다). 두 단계 구조(`rtp`)에서는 손해가 더 크고 ViViD 밤의 스케일도 나빠진다.
- **두 단계 구조 자체는 문제가 아니다.** 쌍 없는 `rt`는 MS2를 거의 유지하고(+0.0017) 네 대상 모두 기준선보다 낮았다(시드 하나, 판정 대상 아님).
- **진단 (`rts`, 쌍을 1단계의 모양에만).** 스케일을 망친 것은 쌍의 절대 깊이였다. 다만 ViViD 실내와 FIReStereo를 고친 것도 그 절대 깊이다. 1단계의 쌍(모양)은 MS2의 모양을 깎는다.
- **다음.** 절대 깊이를 버리지 않고 그 스케일을 바로잡는 쪽을 본다. 쌍 카메라의 초점거리가 서로 다르고(KAIST 약 723 px, Freiburg 약 467 px, TartanRGBT 421 px, 평가 대상 406–437 px), 선생이 카메라를 모른 채 라벨을 냈다.

**진단 `rts` (읽는 법은 2026-11-23 고정, 결과를 보기 전).** `rt`에 쌍을 1단계(선생의 모양)에만 더하고 2단계는 MS2만 쓴다. 아래 값이 `rt`와 `rtp` 가운데 어느 쪽인지 본다. 중간을 넘는 쪽으로 읽고, 중간에서 두 값 차의 10 % 안이면 '가르지 못함'이다. `rt` 쪽이면 원인은 2단계의 쌍(절대 깊이), `rtp` 쪽이면 1단계의 쌍(모양)이다. 시드 0 하나이고 주장의 판정에는 쓰지 않는다.

- **스케일을 망친 것은 2단계의 쌍(절대 깊이)이다.** 절대 깊이를 빼자 STheReO와 ViViD 밤의 스케일 오차가 `rt` 수준으로 돌아왔다. 같이 ViViD 실내와 FIReStereo의 스케일 이득도 사라졌다(0.911 · 0.291).

### 라벨 점검 (학습 없음, 읽는 법은 2026-11-23 고정 — 결과를 보기 전)

쌍의 선생 라벨은 UniDepthV2에 카메라 정보를 주지 않고 뽑았다. 선생이 쌍의 카메라를 잘못 짐작해 절대 깊이가 한쪽으로 쏠렸는지 본다. 세트마다 고르게 뽑은 1,000장에 선생을 두 번 돌린다(카메라 없이 · 실제 카메라 값을 주고).

| 세트 | 실제 초점 (px) | 선생이 짐작한 초점 | 깊이 비 (카메라 없이 / 주고) | 읽기 |
|---|---|---|---|---|
| KAIST (640×512) | 723 | — | — | — |
| Freiburg (640×298) | 467 | — | — | — |
| TartanRGBT (640×512) | 421 | — | — | — |
| LLVIP (640×512) | 모름 | — | 잴 수 없음 | |
| MS2 RGB (1224×384, 정답 있음) | 765 | — | 정답 대비 스케일 오차 — → — | — |

- 사진별 깊이 비의 중앙값이 1.15 이상이면 '멀게 부풂', 0.87 이하면 '가깝게 쏠림', 사이면 '차이 작음'이다.
- MS2 RGB에서는 정답과 견준다. 카메라 값을 줬을 때 스케일 오차 중앙값이 0.01 넘게 줄면 '바로잡음', 늘면 '나빠짐'이다.
- 다음 일도 미리 적는다. 주행 쌍(KAIST · Freiburg)에 '멀게 부풂'이 있고 MS2가 '나빠짐'이 아니면 라벨을 카메라 값으로 다시 뽑는다. 셋 다 '차이 작음'이면 라벨의 스케일은 원인이 아닌 것으로 본다. MS2가 '나빠짐'이면 카메라 값을 주는 길을 믿지 않는다.
- 카메라 값의 근거: KAIST는 논문의 세로 화각 39°, Freiburg는 저자 코드 저장소의 보정값을 우리 묶음의 자르기 · 줄이기에 맞춘 것(공개 영상이 왜곡을 편 것인지는 모른다), TartanRGBT는 공개 저장소의 보정 파일, MS2는 calib.npy다.
- 한계: 카메라 값을 준 쪽이 정답은 아니다. 쌍에는 깊이 정답이 없어 MS2 한 곳에서만 정답과 견준다.

## 팔

| 팔 | 내용 |
|---|---|
| `base` | 기준선. Depth Anything V2 ViT-L을 MS2 열화상과 LiDAR 정답으로 미세조정 |
| `rt` | 두 단계: 열화상용 상대 깊이 모델을 학습해 고정 → 그 위의 작은 모듈만 학습. MS2만 |
| `rtp` | `rt` + 쌍. 1단계에 선생의 모양, 2단계에 선생의 절대 깊이 |
| `rts` | `rt` + 쌍을 1단계에만 (진단) |
| `mtd` | `base` + 쌍의 선생 절대 깊이 (MonoTher-Depth의 방식을 평가와 무관한 쌍으로 옮긴 비교 팔) |
| `sep` · `ours` | 모양 + 스케일 학생 (본 실험 3). `ours`는 쌍을 더한 것 |
| `pl` · `plv` · `tr` | 앞선 실험의 팔 (모양만 가르치는 의사 라벨 · 고정한 공식 모델 위의 모듈) |

쌍은 KAIST 보행자 · LLVIP · Freiburg Thermal · TartanRGBT 37,233쌍이고 평가 대상의 영상은 넣지 않는다. 선생 라벨은 작업을 시작할 때 한 번 뽑는다.

## 판정 기준

결과를 보기 전에 고정했다. 고정한 시각과 바꾼 경위는 상세 기록에 있다.

- **평가.** 정답이 0.001–80 m인 화소에서 사진마다 지표를 구해 평균한다. 주 지표는 raw AbsRel이다. MS2는 낮 · 밤 · 비의 평균이고, ViViD는 선행 논문처럼 정답의 테두리를 빼고 잰다.
- **대상별.** 팔 − `base`의 raw AbsRel 차가 −잡음 폭보다 작으면 '개선', +잡음 폭보다 크면 '나빠짐'이다. 잡음 폭은 `base`의 시드 범위이고 위의 바닥보다 좁게 잡지 않는다(새 대상 둘은 0.0013).
- **여러 곳에서 개선 (주장이 선다).** MS2 유지, 나빠진 대상 없음, 넷 가운데 둘 이상 개선.
- **구조 점검.** MS2 val AbsRel의 마지막 세 epoch 평균이 `base` + 0.005 이하.
- 시드가 하나인 팔은 판정하지 않는다. 평가 대상은 학습과 설정 고르기에 쓰지 않는다.

## 실행

H200 요청 이슈의 실행 명령은 한 줄이다. `LINKS`는 묶음을 받을 곳의 목록을 가리키는 값이고 저장소에는 적지 않는다.

```bash
bash run.sh check LINKS=<값>                               # 1–2분, 환경 · 묶음 접속 확인 (GPU 할당 1)
bash run.sh smoke ARMS=base,mtd,rt,rtp LINKS=<값>          # 작은 묶음으로 끝까지 (GPU 할당 7, 8분)
bash run.sh all ARMS=base,mtd,rt,rtp SEEDS=0 LINKS=<값>    # 본 실험 4 (12–13시간)
bash run.sh all ARMS=rts SEEDS=0 LINKS=<값>                # 본 실험 4의 진단 (4.5–5시간)
bash run.sh labelcheck LINKS=<값>                          # 라벨 점검 (학습 없음, 10–15분)
```

결과 표와 판정은 화면 끝에 찍히고(`[표1]`–`[표6]`, `[판정]`, `[비교]`), 결과 파일은 `/app/output/<작업>/results.zip`이다. 화면 줄 머리는 라벨 점검만 `[labelcheck]`이다. 나머지 모드(`teacher` · `relcheck` · `eval`)와 인자는 `run.sh` 맨 위에 있다. 로컬 시험은 `tests/run_local.sh`(CPU, 메모리 3 GB 안)다.

| 쌍 (깊이 정답 없음) | KAIST 보행자 · LLVIP · Freiburg Thermal · TartanRGBT | 9,546 · 5,163 · 10,438 · 12,086 |

묶음과 받는 주소는 저장소에 없다(다시 배포하면 안 되는 데이터다). STheReO의 정답은 LiDAR를 열화상 시점으로 직접 옮겨 만들어 다른 대상보다 품질이 낮다.
