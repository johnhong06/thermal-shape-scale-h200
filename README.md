# thermal-shape-scale-h200 — 처음 보는 환경의 열화상 깊이 추정

열화상 한 장으로 실제 거리(m)를 추정하는 모델이 학습에 쓰지 않은 열화상 데이터에서도 되게 하려는 실험의 H200 실행 묶음이다. 깊이 정답은 MS2에만 있다. 데이터와 가중치는 저장소에 없고 실행할 때 받는다.

설계, 판정 기준과 읽는 법을 결과 전에 고정한 경위, 데이터를 만든 방법은 [docs/DETAILS_ko.md](docs/DETAILS_ko.md)에 있다.

`base`는 '두 단계 구조 + 쌍' 실험의 값, `rtj`는 '조정' 실험의 값이고 나머지는 '카메라 정보' 실험의 값이다.

- **틀리는 것은 모양이 아니라 절대 거리다.** 사진마다 스케일만 맞추면 `base`의 오차는 FIReStereo 0.69 → 0.30, ViViD 실내 2.12 → 0.17이 된다.
- **두 단계 구조(`rt`)는 세 시드에서 판정 기준을 채운다.** MS2를 지키고 네 곳이 모두 개선이다. 크게 준 곳은 FIReStereo와 ViViD 실내이고, ViViD 밤과 STheReO의 차는 잡음 폭을 겨우 넘는다.
- **쌍만 더하면 한쪽은 고치고 다른 쪽은 망친다.** ViViD 실내 · FIReStereo는 좋아지고 STheReO는 나빠진다.
- **기준 초점 환산에 크기 바꾸기 증강을 함께 쓰면 그 부작용이 사라진다.** 세 시드에서 처음 보는 네 곳의 평균이 0.861에서 0.251로 준다. 대신 MS2가 0.011 나빠지고 ViViD 밤을 가깝게 예측해(0.134 → 0.181) 판정 기준은 채우지 못한다.
- **선행 방법도 같은 곳에서 틀린다.** MonoTher-Depth를 저자의 공개 가중치로 재면 MS2 0.0713 · ViViD 밤 0.1529로 논문 값이 재현되고, 나머지 세 곳은 0.70 · 2.29 · 0.54로 `base`와 비슷하다(네 곳 평균 0.920). 표는 11절에 있다.
- **`rtk`의 손해와 STheReO의 이득은 같은 곳에서 온다.** 크기 바꾸기 증강을 빼면 MS2 0.0727 · ViViD 밤 0.1282로 돌아오지만 STheReO가 0.55로 `base`보다 나빠진다(12절, 시드 0).
- **1단계에도 쌍의 촘촘한 깊이를 넣으면 모양은 좋아지지만, raw 오차는 줄지 않는다.** ViViD 실내의 모양 오차가 17–23 % 줄었지만 2단계의 배율이 흔들렸다(13절).
- **1단계는 원래 모델을 붙잡아 두는 것보다 쌍의 촘촘한 깊이로 배우는 쪽이 모양에 낫다(14절, 작업 A).** 빼 둔 카메라(Freiburg)에서 쌍이 모양 오차를 0.110 → 0.088로 줄였다. 인코더를 고정하거나(0.097) 원래 모델의 토큰에 맞춰도(토큰마다 0.092 · 관계 0.087) 더 낫지 않다.
- **조정 `rtj`는 채택 기준을 넘지 못했다.** MS2 val 0.0793으로 기준 0.0774보다 높다. 그래서 세 시드의 본 실험은 `base` · `rt` · `rtk`로 했다.

### 10. 초점거리 민감도 (`rtk`, 시드 0)

`rtk`는 평가 때 카메라 값을 받는다. 그 초점거리(fx · fy)를 0.8 · 0.9 · 1.1 · 1.2배로 틀리게 줬을 때의 raw AbsRel을 잰다(주점은 그대로). 읽는 법은 결과 전에 고정했다(2026-11-25).

### 11. 선행 방법을 같은 평가 세트에서 (MonoTher-Depth, 학습 없음)

MonoTher-Depth 논문은 MS2와 ViViD 밤의 값만 보고했다. 나머지 세 곳을 채우려고 저자가 공개한 코드(고정 커밋)와 MS2로 학습한 가중치를 받아 우리 평가 세트에서 잰다. 읽는 법은 결과 전에 고정했다(2026-11-25).

- 입력 전처리와 모델 설정은 저자의 것을 그대로 쓴다. MS2에는 저자의 MS2 설정을, 나머지에는 저자가 ViViD zero-shot에 쓴 설정을 쓴다. 채점은 우리 팔과 같은 규칙이고 저자 코드의 규칙과도 같다.
- 먼저 재현을 확인한다. MS2 평균 AbsRel이 0.072 ± 0.003, ViViD 밤이 0.153 ± 0.008 안이면 재현된 것으로 보고 나머지 칸을 채운다. 벗어나면 채우지 않고 전처리와 설정을 먼저 본다.
- 논문의 기준선(Depth Anything 미세조정)은 가중치가 공개되지 않아 잴 수 없다.

### 12. 보완 실험: 크기 바꾸기 증강 없이 카메라 정보 쓰기 (`rtfn` · `rtc`, 시드 0)

### 14. 모양 실험: 1단계를 무엇으로 가르칠까 (`shape` 모드, 시드 0)

1단계(모양)에 넣을 수 있는 장치를 하나씩 더해, 처음 보는 열화상에서 모양이 나아지는지 1단계만 재서 가린다. 2단계는 거치지 않는다. 특징 정렬은 '무엇에 맞추나'와 '어떻게 맞추나'를 2×2로 나눴다. 맞추는 곳은 모두 인코더 마지막 층의 패치 토큰이고, 목표는 학습을 시작한 원래 모델(고정)이 낸 토큰이다.

| 변형 | 1단계에 쓰는 것 | 묻는 것 |
|---|---|---|
| `nopair` | MS2의 LiDAR만 (지금의 1단계) | |
| `pair` | + 쌍 셋(KAIST · LLVIP · TartanRGBT)의 선생 깊이. Freiburg는 빼 둔다 | 기준 |
| `edge` | `pair` + 쌍 라벨에 경계 손실 (비중 2) | 출력 쪽 감독으로 경계가 사는가 |
| `freeze` | `pair`에서 인코더를 고정 (헤드만 학습) | 원래 모델을 그대로 두면 어떤가 |
| `thr_cos` | `pair` + 같은 열화상을 원래 모델에 넣은 토큰에 토큰별 코사인 (여유 0.85, 비중 1) | 원래 모델에서 멀어지지 않게 |
| `thr_gram` | `pair` + 같은 목표에 패치 사이 관계를 맞춤 (비중 5) | 〃 관계만 |
| `rgb_cos` | `pair` + 짝 RGB를 원래 모델에 넣은 토큰에 토큰별 코사인 (여유 0.85, 비중 1). RGB가 어두운 패치는 뺀다 | RGB 쪽으로 끌어오기 |
| `rgb_gram` | `pair` + 짝 RGB 목표에 패치 사이 관계 (비중 5) | 〃 관계만 |

관계 비중 5는 처음 한 걸음에 토큰을 당기는 힘이 토큰별 코사인(비중 1)과 같도록 실제 쌍에서 맞춘 값이다. 작업은 둘로 나눈다. 작업 A는 `nopair` · `pair` · `freeze` · `thr_cos` · `thr_gram`(원래 모델 지키기 쪽), 작업 B는 `pair` · `edge` · `rgb_cos` · `rgb_gram`(RGB에서 가져오기 쪽)이다. `pair`를 두 작업에 다 넣어 같은 설정을 두 번 돌린 차를 잡음 폭으로 쓴다.

읽는 법은 결과 전에 고정했다(2026-11-26).

- 방식은 빼 둔 Freiburg(학습에 쓰지 않은 카메라)에서 잰 모양으로 고른다. 열화상의 예측을 짝 RGB의 선생 깊이와 견주고, 사진마다 스케일 · 기준점을 맞춘 뒤의 AbsRel을 쓴다. 처음 보는 네 곳의 값은 적기만 하고 고르는 데 쓰지 않는다.
- 잡음 폭은 두 작업의 `pair` 값의 차다(지표마다). 그 차가 `pair` 값의 2 %보다 작으면 2 %를 쓴다.
- '좋아짐'은 빼 둔 쌍의 AbsRel이 `pair`보다 잡음 폭 넘게 낮고, MS2 val이 `pair`보다 잡음 폭 넘게 높지 않은 것이다. 빼 둔 쌍이 잡음 폭 넘게 높으면 '나빠짐', 나머지는 '차이 없음'이다.
- 특징 정렬 넷은 목표의 효과(짝 RGB − 같은 열화상, 두 형태의 평균)와 형태의 효과(관계 − 토큰별, 두 목표의 평균)로도 읽는다.
- '좋아짐' 가운데 빼 둔 쌍의 AbsRel이 가장 낮은 하나를 2단계까지 붙여 돌린다. 처음 보는 네 곳은 그때 판정한다. 특징 정렬이 이기면 그 형태에서 층과 비중을 한 번 더 본다. 아무것도 '좋아짐'이 아니면 이 설정의 특징 정렬은 모양을 고치지 못한다고 적고 2단계로 넘어간다.

칸은 사진마다 스케일 · 기준점을 맞춘 뒤의 AbsRel이고, 괄호는 경계 F1(높을수록 좋음)이다.

작업 A(2026-11-26, 777분)에서 넷이 끝났다. `thr_gram`은 학습 45분째에 작업 폴더의 쌍 라벨과 학습 환경이 없어져 멈췄다. 코드는 학습 중에 파일을 지우지 않으므로 작업 밖에서 폴더가 비워진 것으로 보고, 이 변형만 다시 돌렸다(2026-11-27, 297분, 끝까지 돎).

- `thr_gram`은 빼 둔 쌍에서 0.0874로 `pair`(0.0880)와 0.7 % 차이다. 잡음 폭의 하한(`pair`의 2 %)보다 작아서 작업 B와 상관없이 '차이 없음'이다. MS2 val은 더 낮아 지킴을 넘는다. 처음 보는 네 곳은 평균 1.6 % 높다(적기만 함).
- 학습 중 정렬이 당기는 힘은 깊이 손실의 0.05–0.11배로 약했다(`thr_cos`는 0.32–0.59). 관계는 원래 모델 쪽에 가깝게 남았지만(빼 둔 쌍에서 원래 모델과의 유사도 0.890, `pair` 0.787) 모양은 그대로다.

- 처음 보는 네 곳의 경계 F1은 모두 0.02 아래라 견주지 않는다.

### 15. RGB 기준: 어둠에서 RGB 카메라의 깊이 · RGB 모델을 열화상에 그대로 (`rgbref` 모드, 학습 없음)

논문의 출발점("밤 · 어둠에서는 RGB 카메라보다 열화상이 깊이를 더 잘 준다")을 우리 데이터로 확인하고, 표 I의 'RGB 모델을 열화상에 그대로' 줄을 채운다. 모델은 RGB 용 metric 모델 UniDepthV2-L이고(쌍의 선생과 같은 가중치) 카메라 값을 준다. 읽는 법은 결과 전에 고정했다(2026-11-27).

- **RGB 카메라:** ViViD의 같은 프레임을 RGB 카메라로 — 밤 야외 2,019 · 낮 야외 2,213 · 실내 1,947장(어두운 시퀀스 셋 1,201 · 밝은 둘 746). 정답은 같은 LiDAR를 RGB 시점으로 옮긴 것이다.
- **RGB 모델에 열화상:** 열화상 평가 세트 전부. 입력은 우리 모델과 같은 톤 처리를 세 채널로 겹친 것이다.
- 채점은 우리 팔과 같다. 열화상 모델(MonoTher-Depth · `base` · 우리 방법)과의 비교는 앞선 작업의 결과로 로컬에서 한다. 시점이 달라 정답 화소가 다르므로 세트 단위로만 견준다.

읽는 법:

- **어둠이 RGB를 망치는가:** RGB 카메라의 raw AbsRel을 낮 야외 → 밤 야외, 실내 밝음 → 실내 어둠으로 견준다. 같은 모델 · 같은 카메라라 차이는 빛 때문이다. 어두운 쪽이 높을 때만 "어둠에서 RGB 깊이가 나빠진다"고 적는다.
- **RGB 카메라 대 열화상:** 조건(밤 야외 · 실내 어둠 · 낮 야외 · 실내 밝음)마다 RGB 카메라의 raw AbsRel을 열화상 모델 둘(MonoTher-Depth · 우리 방법)과 따로 견준다. 열화상 모델이 더 낮은 조건에서만 "그 조건에서 열화상이 RGB 카메라보다 낫다"고 적고, 어느 모델이 그런지 함께 적는다. 낮 야외 · 실내 밝음은 대조군이다.
- 동기 그림은 밤 야외 · 실내 어둠에서 한 장씩이다. 사진은 저장된 16장(실내는 그중 어두운 시퀀스의 것) 가운데 RGB 모델과 우리 방법의 오차가 각 세트 평균에 가장 가까운 한 장으로 고른다(대표 사진, 손으로 고르지 않음).
- 'RGB 모델을 열화상에 그대로'는 표 I에 그대로 적고 판정하지 않는다.

## 판정 기준

결과를 보기 전에 고정했다. 평가는 정답이 0.001–80 m인 화소에서 사진마다 지표를 구해 평균한다. 팔 − `base`의 raw AbsRel 차가 잡음 폭(`base`의 시드 범위)을 넘게 작으면 '개선', 넘게 크면 '나빠짐'이다. 주장이 서려면 MS2 유지, 나빠진 대상 없음, 넷 가운데 둘 이상 개선이어야 한다. 시드가 하나인 팔은 판정하지 않는다.

## 실행

```bash
bash run.sh check LINKS=<값>                               # 환경 · 묶음 접속 확인 (1–2분, GPU 할당 1)
bash run.sh all ARMS=base,mtd,rt,rtp SEEDS=0 LINKS=<값>    # 5. 두 단계 구조 + 쌍 (12–13시간)
bash run.sh labelcheck LINKS=<값>                          # 6. 라벨 점검 (13분)
bash run.sh all ARMS=rt,rtk,rtf,rtn SEEDS=0 LINKS=<값>     # 7. 카메라 정보 (8.5시간)
bash run.sh all ARMS=rtj SEEDS=0 LINKS=<값>                # 8. 조정 (4.7시간)
bash run.sh all ARMS=base,rt,rtk SEEDS=1,2 LINKS=<값>      # 9. 본 실험의 시드 1 · 2 (12시간쯤)
bash run.sh all ARMS=rtk SEEDS=0 FSWEEP=0.8,0.9,1.1,1.2 LINKS=<값>   # 10. 초점거리 민감도 (4시간쯤)
bash run.sh prior LINKS=<값>                               # 11. 선행 방법 평가 (1시간 안쪽)
bash run.sh all ARMS=rtfn,rtc SEEDS=0 FSWEEP=0.8,0.9,1.1,1.2 LINKS=<값>   # 12. 보완 실험 (5.6시간)
bash run.sh all ARMS=rtkp,rtfnp SEEDS=0 LINKS=<값>             # 13. 모양도 쌍으로 (7시간쯤)
bash run.sh shape ARMS=nopair,pair,freeze,thr_cos,thr_gram LINKS=<값>   # 14. 모양 실험 작업 A (15시간쯤)
bash run.sh shape ARMS=pair,edge,rgb_cos,rgb_gram LINKS=<값>            # 14. 모양 실험 작업 B (15시간쯤)
bash run.sh rgbref LINKS=<값>                              # 15. RGB 기준 (1시간쯤)
```

`LINKS`는 묶음을 받을 곳(Google Drive)의 목록을 가리키는 값이고 저장소에는 적지 않는다. 2026-11-24부터는 묶음을 Hugging Face의 비공개 데이터 저장소에서 받는다(Drive의 하루 받기 한도에 걸려서 옮김). 이때는 `LINKS=<값>` 대신 `DATA_REPO=<계정>/<저장소> DATA_TOKEN=<읽기 전용 토큰>`을 주고, 이 둘도 저장소에는 적지 않는다. 결과 표는 화면 끝에 찍히고 결과 파일은 `/app/output/<작업>/results.zip`이다. 나머지 모드와 인자는 `run.sh` 맨 위에 있다.
